# 事实一致性核查报告（离线、可复现）

> **合成数据声明**：本报告只描述 `fault_corpus.jsonl` 里这 60 条人工合成的用例，
> **不代表真实模型的事实一致率**。真实云端事实一致率需要用户配置 API Key 后在设备上单独实测；
> 本脚本不计算 p50/p95 延迟、不预测真实成功率、不做健康/心理诊断、不编造因果或效率百分比。

## 1. 核查了什么

- 任务集：`fault_corpus.jsonl` 的 **60 条内容样本**（网络类 20 条没有树，不参与）。
- 底稿：`summary_fixture.json` 的 `primary`（唯一数字来源，未混用 `zero`）。
- 核查对象：**最终会显示给用户的那棵树** —— `direct/repaired` 用 `extract → normalize` 的结果，`fail` 用规则兜底树。

三类事实声明：

| 类型 | 怎么认 | 什么算不一致 |
|---|---|---|
| A 数字 | 文本里出现的每个整数 | 不在底稿白名单（primary 全部数值 + 科目分钟 + 0） |
| B 科目 | 文本里出现底稿科目名 | 同句的分钟数 ≠ 底稿；或出现底稿外科目 |
| C 环比方向 | 文本带**周对比语境**（环比/比上周/上周/本周）且含方向词 | 写了「减少/下降」或「持平」，而底稿是环比增加 50% |

## 3. 不一致清单

**无。** 60 棵树里的每一条数字/科目/方向声明都能在底稿里对上。

这个 100% 是**预期内**的，也说清楚它证明了什么：

- 这份底稿的文案本来就是按底稿数字生成的，所以「本来就对」是前提，不是结论；
- 它真正证明的是：**经过抽取 / 规整 / 截断 / 规则兜底之后，最终显示的树没有把数字改错、改丢或换成别的值**；
- 它**不能**说明真实模型的事实一致率——那要用真实 API 实测。

## 4. 反例自检（证明不是「永远 100%」）

每次运行都会现场构造 4 棵树跑一遍，任何一条判错就非零退出：

| 用例 | 结果 | 说明 |
|---|---|---|
| 含底稿外数字（999） | ✅ 抓到/通过 | 不一致声明 1 条，其中含 number 类：true |
| 环比方向写反（减少） | ✅ 抓到/通过 | 不一致声明 1 条，其中含 direction 类：true |
| 科目数字错误（数学 40 分钟） | ✅ 抓到/通过 | 不一致声明 1 条，其中含 subject 类：true |
| 完全合规树（规则树本身） | ✅ 抓到/通过 | 不一致声明 0 条（应为 0） |

## 5. 口径细节与边界

1. **只核对最终树**：`direct/repaired` 走 `extract → normalize`，`fail` 走 `buildRuleTree`，跟真实链路一致。
2. **C 类的语境限定**：样本里有一条行动建议「减少中断次数」，它说的是少被打断，不是「本周比上周减少」。
   若只按字面抓方向词，这 8 条会被误判成事实错误，所以方向声明要求文本同时带周对比语境。
3. **白名单是动态生成的**：从 `primary` 里递归取全部数值 + 各科目分钟 + 0，没有手写死。
4. **B 类只在同句出现数字时才计数**：像「数学占比最高」「优先补英语」这种定性表述不产生数字核对，
   但一旦出现底稿外的科目名（如「化学」）仍会被判不一致。
5. 不计算 p50/p95、不预测真实模型表现、不做健康/心理诊断、不编造因果和效率百分比。
6. 全部为合成数据，比例是人为编排的测试配额，不能用来估计真实模型的任何比率。
