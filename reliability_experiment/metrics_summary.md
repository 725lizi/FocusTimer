## 口径要点（防止误读）

1. **指标 1、2 是“模型/原始响应”层面**，指标 4、5 是“完整链路兜底之后”层面，不能混为一个成功率。
2. 中间还有两个过渡值：G2 无兜底时成功率 51/60 = 85.0%（直接 27 + 修复 24），
   其中抽取阶段修复贡献 8 条（去围栏 4 + 去口语 4）；G2 软 Schema 全量合规率 47/60 = 78.3%。
3. 指标 3 的 100% 是“经抽取/规整/截断/兜底后最终树没把底稿数字改错”，**不代表真实模型事实一致率**。
4. 规则兜底树自检：19 个节点、深度 3、硬逻辑通过、软 Schema 通过，树内数字全部来自底稿白名单。
5. 全部为合成数据，比例是人为编排的测试配额，不能用来估计真实模型的任何比率；
   真实成功率、真实事实一致率、p50/p95 延迟、真实错误分布，均需设备实测并单独标注。

## 真实 API 实测结果（20 次，独立于离线合成数据）

- 模型/端点：`deepseek-chat`，`https://api.deepseek.com/chat/completions`；stream=true、temperature=0.4、max_tokens=900
- 设计：5 份合成底稿 × 每份 4 次 = 20 次真实联网调用
- 三类计数：**direct 20 / repaired 0 / fail 0**（模型全部直接可解析，未触发修复或规则兜底）
- 来源：llm 20 / rule 0；HTTP 非 200 次数 = 0
- 接口级延迟：**p50=1362.1ms、p95=1833.7ms**（nearest-rank），min=1117.7、max=1935.4
- 事实一致性：**196/196 = 100%**（仅核对模型产出数字；本次无 fail，规则树未参与）
- 独立复核：`verify_live_independent.mjs` 10 项全 PASS
- 边界：只描述这 20 次，不外推总体成功率；正常调用未演练降级，降级证据以离线故障注入（#86）与 G0–G3 消融（#87）为准；产物见 `deepseek_bench_results.json` / `deepseek_bench_report.md`
