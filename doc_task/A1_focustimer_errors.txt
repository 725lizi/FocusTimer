1. 报错现象
编译阶段抛出大量类型检查错误，常见报错：
• Object literal must correspond to some explicitly declared class or interface (arkts-no-untyped-obj-literals)

• Argument of type 'xxxValues' is not assignable to parameter of type 'Record'
• Invalid regular expression: Range out of order in character class
• '@Entry' should have a parameter 或 Unable to resolve signature of class decorator
• Module '"@kit.ArkUI"' has no exported member 'DrawingRenderingContext'
多出现于：数据模型定义、分布式数据对象操作、工具类封装、UI 组件装饰器使用、正则表达式解析等场景。
2. 核心报错原因
• 对象字面量无类型：ArkTS 强制所有对象字面量必须明确实现接口或类，不允许无类型对象。
• any/unknown 滥用：ArkTS 不允许使用 any/unknown，需显式声明具体类型或联合类型。
• 索引签名被禁用：[key: string]: any 等索引签名语法不被支持，需改用具体字段或 Map 类型。
• 类型不匹配：自定义类型与系统 API 期望类型不兼容。
• 正则表达式转义错误：反斜杠层级在 ArkTS 中需特殊处理，字符类范围错误。（项目 AIAnalysisService 中实际踩坑）
• 装饰器参数缺失：@Entry 使用规则误用导致编译失败。
• 未导出或未提供类型：某些 Kit 模块内部类型未开放，直接导入报错。

4. 完整解决方案
• 为对象定义 interface：所有对象字面量显式声明类型，如 SubjectTagValues、NoteValues、OfflineQueueItem 等。
• 显式类型替代 any：使用具体类型、联合类型或 Object | undefined。
• 移除索引签名：改用具名字段；如需动态键值，使用 Map<string, number> 替代。
• 修正正则转义：ArkTS 中正则表达式的反斜杠转义规则与标准 TypeScript 一致，不需要多重转义。如 \$ 表示匹配美元符号，\\[ 表示匹配左方括号。

• @Entry 参数规则：卡片页面使用 @Entry 不带参数，普通页面可带参数但需符合规范。
