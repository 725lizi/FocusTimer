# Codex 任务单 P1：体验深点打磨 + 与 AI 串联成「学习闭环」完整故事线

> 性质：一组**有先后顺序**的迭代任务（P1-1 → P1-5），不是一次性大改。
> 面向：Codex（实现方）。本单只描述需求、数据契约、模块边界与验收，**不规定具体代码写法**；但必须严格遵守下面的「全局铁律」。
> 建议触发时机（产品侧）：日常真用 1~2 周、知识库里攒到 ≥ 20~30 段真实笔记后再开工，避免在没有真实数据时做空包装。指令可先备好。

---

## 0. 一句话目标
把现在三条各管各的线——**专注计时、笔记、AI（周报 / RAG 问答）**——串成一条可被用户感知、也能在面试中完整讲述的「学习闭环」：

> 选科目开始专注 → 结束随手记「学了什么 / 卡在哪」（自动绑定本次专注与科目）→ AI 即时复盘 → 专注小结和笔记一起进个人知识库 → 周末 AI 周报不仅统计时长，还基于本人笔记/卡点讲「学了什么、哪里薄弱、下周重点」，结论可溯源，没网就降级规则版。

## 1. 现状与断点（已逐文件核对，作为改造依据，勿重复发明）
- 专注记录 `StudySession`（`services/LearningAnalysisService.ets:7`）只有 `id/startTime/duration/tags/isInterrupted/interruptCount`，**没有"本次学了什么/卡点"字段**；计时结束 `Index.showLearningReport()`（`pages/Index.ets:495`）目前只 `console.info`，**没有真正给用户复盘**。
- 笔记 `NoteValues`（`pages/Notes.ets:21`）带 `subject_tag_id / created_at / updated_at / is_encrypted`，已能被 RAG 索引（来源类型 `note`）。
- RAG 来源类型 `ChunkSourceType = 'note' | 'focus'`（`services/rag/RagTypes.ets:5`）**已预留 `'focus'` 但全程未使用**——本单正式启用它。
- AI 周报 `ReportPromptBuilder.buildSummary()`（`services/ai/ReportPromptBuilder.ets:49`）**只聚合时长/次数/科目/中断，完全没吃笔记内容**，所以 AI 只知道"学了多久"，不知道"学了什么、哪里不会"。
- RAG 问答只在 `pages/KnowledgeBase.ets` 独立页面、需手动提问，与专注结束、统计页周报之间没有入口联动。

## 2. 全局铁律（每条都必须满足，和既有架构保持一致）
1. **纯逻辑下沉、可离线单测**：聚合、拼装、决策、模板等"给定输入必得相同输出"的逻辑，全部放到 `services/` 下的纯类，不 import UI / 系统 API；页面与设备层只做调用与呈现。
2. **设备层做薄**：数据库、网络、传感器式能力只做"调系统 API + 转发已测结果"，不写判断分支。
3. **永远有本地兜底**：任何 AI 能力都必须"先备好规则版、再请求大模型"，无网 / 无 Key / 超时 / 错 Key / 空返回都能自动降级，复用现有 `ReportStrategy`、`HttpErrorMapper`、`NetState`、`ApiKeyStore` 的决策与错误归类思路，不另起炉灶。
4. **Key 绝不写进代码或日志**，沿用现有 KeyStore；加密笔记（`is_encrypted=1`）一律不进向量库。
5. **小步提交、每步 CI/单测保持绿**：一个子任务一个 commit，不允许攒一个巨大改动；每个子任务都要能独立编译、独立回滚。
6. **旧数据兼容**：数据库结构演进必须走版本迁移，老用户的历史专注、笔记、向量块一条都不能丢；新增字段全部可选、对历史数据有合理默认。
7. **功能开关（feature flag）**：本单所有新能力默认挂在一个本地开关后面（放 `RagConfig` 同风格的配置处），出问题可一键关回当前版本，主计时链路任何时候不受影响。
8. 不破坏现有 168 个单测；新增纯逻辑必须配套单测，交付时说明单测总数从 168 增至多少。

## 3. 数据契约（只定字段与语义，不写实现）

### 3.1 新增「专注小结」实体 FocusReflection
表示"一次专注结束后，用户对这一段的轻记录 + 系统复盘"。建议字段：
- `sessionId: string`（关联对应 StudySession，一对一）
- `subjectTagId: string`、`subjectName: string`（冗余名称便于展示，未选科目为"未分类"）
- `startTime: number`、`endTime: number`、`durationMinutes: number`
- `interruptCount: number`
- `userNote: string`（用户随手填的"学了什么/卡点"，可为空）
- `aiDebrief: string`（即时复盘文本，规则版或 AI 版）
- `debriefSource: 'rule' | 'llm'`（复盘来源，便于界面打标签）
- `indexed: boolean`（是否已进入 RAG 向量库，防重复索引）
- `createdAt: number`

### 3.2 关系库新增表 `focus_reflection`
- 由仓库层统一读写（建议在 `common/FocusSessionStore.ets` 同层新增对应仓库方法，或新建 `FocusReflectionStore`，对外只暴露"要什么"，不暴露 SQL）。
- 必须包含数据库版本迁移逻辑；提供：插入、按 sessionId 查、按时间范围查本周列表、按科目过滤。

### 3.3 正式启用 RAG `'focus'` 来源
- 一次专注小结向量化时，`ChunkMeta.sourceType='focus'`，`sourceId` 用 `focus:<sessionId>` 保证同一专注重复提交时"先删旧再插新"可覆盖、不产生重复块（复用现有 `replaceSource` 事务语义）。
- 引用标签 `Citation` 在界面上对 `focus` 显示为「专注小结 · 时间」，对 `note` 维持「笔记 · 标题」。

### 3.4 StudySession 的兼容演进
- 不删原字段；如需关联，新增**可选** `reflectionId?: string`，历史数据该字段为空也能正常跑。

## 4. 子任务拆分（按顺序实施）

### P1-1 数据底座：专注小结的存储与纯逻辑组装
**目标**：先把"专注小结"能存、能取、能组装成可向量化/可展示文本，先不接 AI、不改 UI 交互。
- 设备/仓库层：按 3.2 建表与迁移、实现增查方法。
- 纯逻辑新增（可单测）：`ReflectionAssembler`
  - 输入 FocusReflection 所需原始信息，输出：①一段给用户看的简短小结；②一段给向量化用的纯文本（含科目、时长、用户记录、中断情况）；
  - 边界用例必须覆盖：userNote 为空、科目为未分类、中断 0 次/多次、时长非法（0/负数）、文本超长截断。
- 单测要点：空值不崩、字段映射正确、同 sessionId 组装结果稳定（确定性）。
- **退出条件**：建表迁移在老库上验证不丢数据；纯逻辑单测全绿；主计时与现有功能零影响、开关关闭时完全无行为变化。

### P1-2 体验深点：专注结束「轻记录 + 即时复盘」
**目标**：`onTimerComplete` 完成流程里，让用户能顺手记一笔，并立刻得到 3~5 句本次复盘。
- 交互（页面层 `Index.ets` / 可抽组件）：现有"继续专注/休息一下"弹窗基础上，增加一个**可选**输入区"这一段学了什么？卡在哪？"（不填也能正常完成，不允许阻塞主流程）；提交后落库 FocusReflection。
- 编排新增（薄设备层）：`SessionDebriefService`（命名可议），严格走"先规则兜底、再按需请求 AI"：
  - 输入：本次 session 统计 + userNote +（可选）RagRuntime 本地检索到的、与本科目/关键词最相关的几条本人笔记；
  - 输出：简短复盘（鼓励 + 一个可执行改进点），并标注 `rule/llm`；
  - 失败分类与是否降级复用现有策略，不新增一套错误处理。
- 纯逻辑新增（可单测）：`DebriefPromptBuilder`（拼提示词，铁律"数字只能来自输入、不许编造"）、`DebriefRuleTemplate`（无 AI 时的规则模板，多套输入分支）。
- 记录入库后，按 3.3 增量进入 RAG（`sourceType='focus'`）；向量化需要 embedKey，无 Key/无网时跳过向量化但**小结仍正常落库**，下次重建索引可补。
- 单测要点：规则模板各分支、prompt 含真实数字且不越界、AI 失败必回退、userNote 为空也能产出复盘。
- **退出条件**：真机走通"专注→记一笔→看到复盘→知识库里能检索到该 focus 小结"；断网/无 Key 时给规则版且不报错；开关关闭则回到现有完成弹窗。

### P1-3 AI 串联核心：周报从"统计时长"升级为"统计 + 我这周学了什么"
**目标**：让周报能讲学习内容与薄弱点，AI 版与规则版同口径升级。
- 纯逻辑新增（可单测）：`WeeklyLearningDigestBuilder`
  - 输入：本周 StudySession 列表 + 本周笔记 + 本周 FocusReflection 列表；
  - 输出"学习内容底稿"：本周覆盖科目、各科目笔记高频关键词（复用 `extractNoteKeywords`，不要重写分词）、高频卡点词、focus 小结主题、内容最密集的科目；空数据时返回显式的"本周无学习内容"标记。
- 改造 `ReportPromptBuilder`：在现有统计摘要后追加"本周学习内容底稿"，system prompt 增加一段「本周学习内容与薄弱点」，并保持原四段结构或扩展为五段（总体/科目分布/学习内容与薄弱点/专注质量/下周建议），字数上限相应调整；**所有内容必须来自 digest，禁止模型虚构知识点**。
- 同步升级规则版 `LearningAnalysisService.generateWeeklyReport`：无 AI 时也能基于 digest 输出"本周重点/卡点"，保证两条路口径一致、可对照。
- （可选增强，建议做）周报生成时用 `RagRuntime.ask` 的检索能力对"本周最薄弱点"做一次本地 Top-K 检索，把命中的本人笔记作为 grounding 上下文并在周报中标注来源；检索为空就退回纯统计，不允许硬编。
- 单测要点：digest 聚合正确（关键词频次、科目归集、空周）、prompt 包含/缺省内容两分支、规则版与 AI 版口径一致、周一为周起点的边界（沿用现有 getWeekStartTime 测试口径）。
- **退出条件**：同一份一周数据，AI 版与规则版都能说出"学了什么/哪里薄弱"且数字一致；断网自动规则版；现有周报单测全部通过并新增上述用例。

### P1-4 动线串联：让三条线在界面上彼此可达
**目标**：用户不用自己找入口，故事线在 UI 上自然流动。
- 统计页 AI 周报区：周报末尾加「基于我的笔记追问」按钮 → 跳转 `KnowledgeBase` 并预填一个结合本周最薄弱科目的问题（问题文案由纯逻辑根据 digest 生成，可单测）。
- 知识库问答页：加 2~3 个「快捷提问」chip（如"我这周高数卡在哪""帮我复盘本周专注质量"），点击即填入并可直接发起。
- 知识库来源列表/引用标签支持 `focus`：专注小结可被检索到、引用处显示「专注小结」。
- 首页完成复盘（P1-2）提供「查看本周周报」入口跳到统计页。
- **退出条件**：走完"专注→复盘→周报→追问→命中本人笔记/小结"全程无死路、返回键正常；所有跳转在缺少数据（无笔记/无周报）时优雅禁用并提示，不崩。

### P1-5 收口：测试、性能埋点、图表与灰度
- 补齐 P1-1~P1-4 全部纯逻辑单测，给出新增用例清单与新的单测总数。
- 沿用 `[RAG-Perf]` 风格新增 `[Loop-Perf]` 埋点：即时复盘首字/总耗时、周报"统计+内容"增强耗时、focus 小结增量索引耗时（真机数字留档，供性能对比与简历）。
- 更新/新增图（交给文档侧，Codex 只需保证实现与下述叙事一致）：学习闭环数据流图 1 张、专注结束即时复盘时序图 1 张。
- feature flag 默认策略：先默认关闭自测，真机验证一周后再默认开启；保留一键回退。
- **退出条件**：全量单测绿、DevEco 完整构建通过、真机端到端走通闭环、开关切换无残留状态。

## 5. 推荐实施顺序与每步可独立交付
1. P1-1（底座，不改变任何现有界面）→ 合入。
2. P1-2（结束复盘，先能独立用）→ 合入。
3. P1-3（周报升级，串联价值最大）→ 合入。
4. P1-4（动线，把前面能力连起来）→ 合入。
5. P1-5（测试/埋点/灰度收口）。
每步都要：编译通过 → 全量单测绿 → 真机走一遍该步路径 → 单独 commit（信息写明 P1-x 与内容）。

## 6. 总验收清单
- [ ] 老数据库升级不丢数据；新增字段/新表对历史为空情况安全。
- [ ] 学习闭环可端到端走通：专注→轻记录→即时复盘→入个人知识库→周报讲学习内容与薄弱点→一键追问命中本人材料并标来源。
- [ ] `'focus'` 来源正式启用且同 session 重复提交不产生重复块；加密笔记绝不入库。
- [ ] 所有 AI 路径无网/无 Key/出错/空返回都自动回退规则版，界面有来源标签，不崩、不卡死、不编造。
- [ ] 判断逻辑全部在可离线单测的纯类；新增单测齐全、总数较 168 有明确增加；现有 168 测试零回归。
- [ ] feature flag 可一键关回现状，主计时链路在任何分支下都稳定。
- [ ] 真机性能埋点有数字；提交粒度小、每步 CI 绿。

## 7. 风险与回滚
- **风险：AI 串联让周报变慢** → 规则版先出、AI 增量替换（沿用现有流式/先兜底模式）；digest 聚合为本地毫秒级，不阻塞首屏。
- **风险：笔记少时周报"学习内容"空洞** → digest 空内容显式降级为纯统计话术，不硬凑；这也是把开工时机放在"笔记攒厚后"的原因。
- **风险：新表迁移出错** → 迁移逻辑单独可测，先在含历史数据的库上演练，失败不覆盖旧表。
- **回滚**：关闭 feature flag 即回到当前版本；数据表保留不删，避免反复迁移。

## 8. 面试叙事（实现完成后要能这样讲，供对齐方向）
"我发现前三个阶段做完后，专注、笔记、AI 是三条平行线：AI 只统计了学习时长，却不知道我学了什么。P1 我把它们串成学习闭环——专注结束做轻记录并即时复盘，专注小结复用 RAG 的来源抽象（我在类型设计时就预留了 focus 来源）和笔记一起向量化，周报再基于本人材料做 grounded 总结并可溯源。工程上依旧坚持纯逻辑可测、设备层薄、AI 永远有规则兜底、功能可灰度回滚，数据库演进做了向后兼容迁移。"

## 9. 明确不在本单范围
- 不自训模型、不引入新的模型框架；不改主计时状态机本身；不做 UI 视觉大改版。
- 口播稿、博客、正式架构图由文档侧另行产出，Codex 不负责写作。
