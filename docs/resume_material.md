# FocusTimer3 简历素材与岗位方向（阶段 4 · 持续打磨）

> 用法：先确定投的岗位，再从下面挑对应版本的 3~4 条 bullet 贴进简历；所有数字都能在代码/博客/真机日志里找到出处，面试官追问时按"可被深挖的点"展开。专有名词都配了大白话，方便你先看懂再背。

## 一、项目抬头（一句话定位）

**FocusTimer3｜HarmonyOS NEXT 专注计时与 AI 学习助手（个人项目，开源 + 4 篇中英技术博客）**
技术栈：ArkTS / ArkUI 声明式 UI、关系型数据库、@kit.NetworkKit 网络、SSE 流式、DeepSeek 大模型、端侧 RAG（BGE 向量化 + 余弦检索）、单元测试（Hypium，168 例）

## 二、通用版项目描述（方向没定时先用这套，4 条）

- 独立设计并开发一款 HarmonyOS NEXT 原生专注计时 / 学习管理 App，采用「页面—组件—领域—仓库—设备」五层分层架构，将近 800 行首页拆解为 10 个职责单一的组件与纯逻辑状态机，核心判断逻辑全部抽为可离线单测的纯函数，累计 **168 个单元测试**。
- 接入 DeepSeek 大模型实现**流式 AI 学习周报**：基于 SSE 逐字渲染，用有状态解码器解决中文跨包乱码与半包 JSON；设计「先备规则兜底、再请求大模型」的优雅降级，把 HTTP 状态码与系统错误码归一为 8 类，断网 / 错 Key / 超时 / 限流自动回退本地规则版，保证任意异常下用户都有产出。
- 独立实现**端侧 RAG 个人学习知识库**：中文感知切块（220 字 / 30 字重叠）、OpenAI 兼容向量化（BGE，1024 维）、本地 Top-K 余弦检索、关系库持久化，以及「相似度闸门 + 字符预算 + 提示词约束」的防幻觉问答，回答附可追溯的笔记来源；实测 ≤2000 知识块本地检索约 2.4ms、真机提问到首字约 1.3s。
- 工程与安全：API Key 零硬编码、仅存应用沙箱且聊天 / 向量化两把 Key 分离，加密笔记不参与向量化；小步提交保持 CI 持续绿色；输出 4 篇中英双语技术博客与架构 / 数据流图，公开讲清每次技术选型与取舍。

## 三、按岗位分叉（投哪个就用哪个版本，替换上面对应条目）

### A. 移动客户端方向（鸿蒙 / Android）——突出工程与系统能力

- 用 **ArkUI 声明式 UI** 搭建 5 个页面、10 个可复用组件，props 向下 / 回调向上实现单向数据流；用显式 `@State` 驱动替代方法绑定，解决声明式框架依赖追踪导致的输入框不可编辑问题。
- 以**有限状态机 TimerEngine** 统一管理计时的开始 / 暂停 / 继续 / 完成，并修复定时器在页面切换时的泄漏（谁申请资源谁释放）。
- 集成多项 HarmonyOS 系统能力：环境光传感器、跨端接续 Continuation、桌面服务卡片 Form、生物识别加密文件夹、关系型数据库、离线缓存与日历同步。
- 弱网与稳定性：离线优先的本地缓存策略、网络错误分类与统一提示；纯逻辑 / 设备层分层可测，168 个单测覆盖状态机、规则引擎与 AI / RAG 纯逻辑。

### B. AI 应用 / 大模型端侧方向——突出 LLM 与 RAG 落地

- 完成「规则引擎 + 大模型」**混合智能架构**：三条件（开关 / Key / 网络）决策是否请求模型，任何错误除用户主动取消外一律降级到本地结果，并诚实标注输出来源。
- 手写 **SSE 流式解析器**处理半包 / 坏 JSON / `[DONE]`，配合有状态 UTF-8 解码避免中文乱码；流式多结束路径用 settled 标志保证回调幂等、请求对象及时销毁。
- 端到端实现 **RAG**：切块 → 向量化（厂商可配的 OpenAI 兼容客户端，含批量、维度校验、查询前缀）→ 本地余弦 Top-K 检索 → 防幻觉规划（0.2 相似度阈值、1200 字上下文预算、同篇引用聚合、只准用材料的系统提示）→ 流式生成并标注来源。
- 用**分阶段实测数据**支撑选型：本地检索在不同规模下的耗时证明个人量级无需重型向量数据库（YAGNI），真机埋点拆分「本地算力」与「网络 / 模型」两段延迟。

## 四、可被面试官深挖的点（你要能讲 2 分钟的）

1. 为什么这样分层？纯逻辑层和设备层怎么划、为什么测试投入不一样？
2. SSE 流式：半个汉字、半行 JSON 怎么处理？资源怎么释放？
3. 优雅降级：为什么"先把规则版算好攥在手里"？哪些错误兜底、哪个不兜底、为什么？
4. RAG vs 微调 vs 长上下文塞原文，为什么选 RAG？DeepSeek 没有 embedding 你怎么办？
5. 中文切块为什么要重叠、块大小怎么定、超长无标点怎么办？
6. 为什么不用向量数据库？余弦相似度怎么算、复杂度多少、数据量级怎么估？
7. RAG 怎么防幻觉？阈值 / 预算 / 提示词 / 来源标签分别解决什么？
8. API Key 怎么不泄露？两把 Key 为什么分开？
9. 声明式 UI 的 @State 依赖追踪踩坑（输入框为何不可编辑）。
10. 168 个单测怎么分配，为什么网络类不硬 mock？

## 五、岗位方向分析（你现在还没定，给你一个判断）

- **你的差异化标签 = 鸿蒙原生客户端 + 端侧 AI 落地的组合**，这在同龄本科生里不多见。
- **建议主航道：移动客户端开发（鸿蒙 / Android）**。理由：你的工程能力（分层、组件化、状态机、系统能力、测试、性能）全部沉淀在客户端，岗位数量多、可迁移性强；鸿蒙原生岗位虽总量少于 Android，但竞争更小、有生态红利，值得作为第一优先投递方向之一。
- **第二方向 / 加分项：AI 应用工程师（端侧 / 大模型落地）**。你真的做过流式、降级、RAG、防幻觉，而不是调个 API 的 demo，这在 AI 应用岗是实打实的亮点；但纯算法 / 模型训练岗不建议主投（需要算法、论文、训练栈，和你现有积累不匹配）。
- **怎么最终确认**：大三上先按"客户端为主、AI 为特色"准备简历和投递，寒暑假各拿一段实习实际体验，用真实工作内容验证自己更喜欢、更擅长哪条，再在大三寒假前锁定主方向。

## 六、量化数据速查（面试 / 简历随时引用，均有出处）

- 单元测试：168 个（阶段 1 累计 74 → 阶段 2 到 108 → 阶段 3 到 168，其中 RAG 新增 60）
